# SherpaHR · Project Desk

Готовое приложение для работы с проектами, задачами и обсуждениями.
Новое тестовое: **[task_v7.md](task_v7.md)** — развитие существующего продукта.

## Запуск

Нужны Docker Engine с Compose v2 и свободный порт 8097:

```bash
docker compose up --build -d --wait
```

Откройте **http://localhost:8097**. Первый запуск скачивает зависимости и собирает
интерфейс. Последующие запуски используют образ и сохраняют данные в volume.
Другой порт: `PORT=8099 docker compose up --build -d --wait`.

```bash
docker compose logs app
docker compose exec -T app php backend/tests/smoke.php
docker compose down
```

Тесты создают собственную временную БД и сервер; ваши рабочие данные не меняются.
Чтобы заново создать только демонстрационные данные этого Compose-проекта:
`docker compose down --volumes`, затем повторите запуск. Удаление volume стирает
локальные изменения в задачах и комментариях.

## Приложение

- У руководителя активных проектов открывается экран «Требуют внимания».
  Для демо выберите Анну. Начните с просроченной блокировки, откройте задачу
  и прочитайте обсуждение. После изменения статуса или добавления комментария
  список пересчитывается. Данные доступны также через обычное меню проектов.
- В боковом меню — доступные проекты; в проекте — задачи с поиском и фильтром статуса.
- В карточке можно менять задачу, исполнителя, статус и срок, добавлять комментарии.
- Архивные проекты доступны для чтения.
- Переключатель демо-пользователя позволяет посмотреть приложение от разных лиц.
  Это демонстрация прав, **не настоящая аутентификация**; приложение предназначено
  для локальной работы. Compose публикует порт только на loopback.
- Все имена и данные вымышлены. Даты в UTC, сроки создаются относительно первого
  запуска БД и затем сохраняются; приложение не передвигает их при перезапуске.

Техническая справка: [разработка](docs/development.md),
[API](docs/api.md), [контекст продукта](docs/product.md).

## Работа с агентом и сдача

Кандидат самостоятельно выбирает агента, модель, редактор и инструменты.
Сессия или токен организатора не требуются. Порядок журнала и сдачи:
[AGENTS.md](AGENTS.md), [скил отчётности](.agents/skills/sherpa-hr-task-lifecycle/SKILL.md).

Одна центральная issue в `SherpaRPA/SherpaHR` содержит журнал каждого промпта
и действия агента. Решение — в отдельной ветке публичного форка кандидата,
PR открывается внутри этого форка. При сдаче обязательны итоговый отчёт,
проверенный head SHA и комментарий с `@fxpw`. Issue закрывается как сданная
на проверку; PR остаётся открытым.

Если используете чужой код или публичные решения, укажите источник,
условия использования и собственные изменения.

Если для решения нужны новые пути за пределами приложения, добавьте их
в `.gitignore` в секцию `CANDIDATE SOLUTION` перед
защитными исключениями. Секреты и персональные данные не публикуйте.
